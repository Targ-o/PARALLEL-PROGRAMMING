# задание

Модифицировать программу из лабораторной работы №1 для параллельной работы по технологии OpenMP. Провести серию экспериментов с разным количеством потоков (1, 2, 4, 8), разными размерами матриц (20, 200, 400, 800, 1200, 1600, 2000) и разным количеством вычислительных ядер (при наличии технической возможности, иначе использовать фиксированное количество ядер).

Исходные данные: файлы, содержащие значения исходных матриц. Выходные данные: файл со значениями результирующей матрицы, время выполнения, объём задачи, ускорение. Автоматизированная верификация результатов выполняется с помощью Python (NumPy).

# Описание алгоритма

первый цикл перебирает строки первой матрицы, второй цикл перебирает столбцы второй матрицы, третий цикл суммирует произведения соответствующих элементов. Временная сложность O(N³), объём памяти O(N²)

Распараллеливание выполнено по внешнему циклу (по строкам результирующей матрицы)  спомощью #pragma omp parallel for num_threads(threads). Строки матрицы C делятся между потоками, при этом каждый поток записывает результат только в свои строки C[i][*], поэтому гонок данных нет и синхронизация не нужна; матрицы A и B потоки только читают; порядок суммирования по k для каждого элемента такой же, как в последовательной версии, поэтому результат не зависит от числа потоков.

# Что изменено в коде 

1. **Подключён OpenMP.** В Source1.cpp добавлен include omp.h, в CMakeLists.txt добавлены find_package(OpenMP REQUIRED) и target_link_libraries(... OpenMP::OpenMP_CXX). Без этого директива #pragma omp игнорируется и программа работает в один поток.
2. **Функция umnozenie получил threads** и директиву pragma omp parallel for num_threads(threads) перед внешним циклом.
3. **Серия экспериментов в main.** Для каждого размера матрицы умножение запускается для threadList = {1, 2, 4, 8}. Матрицы читаются из файлов один раз на размер, а не на каждый запуск.
4. **Замер времени** выполняется функцией omp_get_wtime() т.е реальрное время
5. **Расчёт ускорения.** Время на 1 потоке принимается за базу: ускорение = T(1) / T(p)
6. **Файл результата** matrix_C_N.txt записывается один раз на размер (после последнего запуска), чтобы не писать большие файлы для каждого числа потоков. Результат не зависит от числа потоков, поэтому верификации это не мешает.
7. **Защита от «тихого» отказа OpenMP.** Если проект собран без /openmp, компиляция завершается ошибкой #error. Кроме того, при старте программа печатает OpenMP check: requested 4 threads, got N (фактическое число потоков в параллельной области).
8. **verity.py и generate_matr.py.** Верификация проходит по всем размерам (matrix_a_N.txt, matrix_b_N.txt, matrix_C_N.txt), генератор сам создаёт папки data и results.
